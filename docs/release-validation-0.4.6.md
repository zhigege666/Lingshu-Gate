# 0.4.6 candidate and publication validation

## Source and patch scope

The candidate starts from main `3e0f101ed858c94841a1f75b3ef23ee4d52e2e1b`,
after PR60 and PR61 and their ordinary CI. Its sole runtime version source is
`src/lingshu_gate/_version.py`. The patch carries the integrated 0.4.5 features
and the account-menu focus fix without changing authorization or optional
executor/OAuth defaults. The occupied `v0.4.5` tag remains at its original
revision; this candidate uses a new `v0.4.6` identity.

The [source/package evidence](benchmarks/gate-main-package-3622c21.json) records
the earlier exact main candidate, static inventories, PEP517/sdist wheel
verification and native schema-worker checks. These are prior evidence, not
0.4.6 artifact hashes. Fresh 0.4.6 checks and hashes must be recorded separately.

## Executed local acceptance and limits

The independently reviewable [PR62](https://github.com/zhigege666/Lingshu-Gate/pull/62)
records 48 owned-adapter boundary regressions and ten actual loopback HTTP/stdio
groups at product source `3e0f101`. It verified 115 Console SHA values, 111
root/legacy asset pairs, root negotiation, query redirects, path rejection,
management permission denials and actual upload/copy-tree/deploy/start/discovery
and stdio invocation. Eight tracked processes were absent after manager exit;
the owned data root was deleted and private receipts were retained.

This fixture uses regenerable synthetic local accounts and data. It does not
create nx5 identities, grants or persistent sessions. Its build plan has no
dependency/install/compile commands. Discovery did not publish classifications
or grant new viewer access. Full Project Delivery Skill acceptance is therefore
separate. Author checks are not an independent implementation review.

Chromium was attempted with its sandbox enabled and reported **No usable
sandbox**. No browser policy was weakened. Four-desktop layout/focus and native
history/fragment/browser navigation remain unexecuted in that environment.
Earlier browser and ordinary main CI receipts retain their exact source scope.
Real OAuth clients, cross-machine acceptance and optional Native/Linux Podman
host provisioning remain outside the current local evidence.

## Mandatory publication gate

Pushing the accepted version change to main invokes the existing
`publish-release` selector. Its credential and immutable-release prechecks
must succeed before creating a new tag and dispatching `release.yml`. No
credential value is read or created by this validation work.

Formal publication requires the existing quality job, five native targets,
Compose, both Core architectures/offline images, application SPDX SBOM, image
reference and `SHA256SUMS`: eleven exact release assets. Verify all job outcomes,
archive checksums, internal inventories, SBOM and source/workflow attestations,
then read back the published title, body and downloadable assets. A candidate,
tag or dispatch receipt alone does not establish publication. Old failed
workflows and denied artifacts are not retried as substitutes for the new gate.

Core architecture and visual-direction decisions are future planning and do
not extend the gate for this already integrated patch.
