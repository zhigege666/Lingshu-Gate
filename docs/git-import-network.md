# Git import and network settings

[简体中文](zh-CN/git-import-network.md) · [Project delivery](project-delivery.md)

## Design and execution boundary

System settings is a first-level Console destination with horizontal tabs. The first tab is Network and dependencies. Named proxy profiles have immutable revisions, explicit disable, reference inspection, optimistic concurrency, redacted status, and controlled tests. Configuration uses `system_settings.manage`; invocation uses `network.use` together with existing operations/tool/token permissions. Neither permission grants the other.

Git acquisition and dependency installation have separate defaults. A project selection is exactly `inherit` (resolve the current default at plan time), `direct` (no proxy), or `profile` (a named revision). npm registry and Python index are separate HTTPS endpoints, never proxy aliases. Credentials are references to the existing encrypted credential store. Ordinary responses, audit payloads, plans, manifests, and artifacts contain no proxy endpoint or secret value. Runtime MCP processes do not inherit delivery network settings.

This development branch implements an optional [Native/Linux rootless Podman executor](native-executor.md). Its factory, observed readiness, durable journal and lifecycle are connected to the existing delivery chain. Trusted HTTPS acquisition owns DNS/proxy/credentials; project scripts receive verified content in a physically offline sandbox. Exact preloaded images, actual namespaces/controllers and bounded workspaces are mandatory. Missing prerequisites fail closed without host fallback. Core remains gateway-only and never touches the engine/socket. Physical host acceptance is still untested; the source version remains 0.4.4 and this work is unreleased.

## Source to delivery

Native adapter code is now present. Administrator provisioning and real acceptance remain separate. The first dependency cache workflow is registry-only npm lock v2/v3; pnpm/Yarn/Python installs and unsafe npm cache shapes fail explicitly. Official pinned npm/pnpm/Yarn tool preparation and selected offline Node build scripts are implemented. See the [execution decision](git-executor-decision.md) and [precise supported matrix](native-executor.md#acquisition-and-package-support). Core remote phase/artifact/runtime delivery remains outside this scope.

The source form accepts HTTPS repository URL, branch/tag/full commit, relative project directory, private repository credential reference, independent Git/install network selections, and Node/Python runtime template. Preview validates input before any network request. A safe executor must resolve a full commit SHA in its actual environment; ambiguous or missing refs fail. The import plan binds that SHA, source selection, credential revisions, network revisions, policy revision, limits, and a digest. Acquisition requires separate explicit confirmation and an idempotency key. It fetches that exact SHA, never re-resolves a moving branch. The executor exports a bounded ZIP without a working Git directory. Gate validates and imports it through `ProjectUploadStore`, then attaches source/file-list digests, repository commit, selected revisions and provenance. It does not create a parallel builder or deployment path.

Preflight and BuildPlan remain inspectable. Dependency installation and build require their own confirmed digest-bound request. Deployment, overwrite, startup, cancellation, and rollback retain the existing Project Delivery boundaries and ownership checks. A new artifact is built in a new directory; a failed import or build cannot replace an existing deployment. Deployment retains existing target compensation and explicit rollback. It does not provide seamless MCP session migration.

## Network and source constraints

Only HTTPS Git transport is supported in this increment. SSH/scp syntax is rejected with an actionable support error; `HTTP_PROXY` does not implement SSH. A future SSH executor needs separately reviewed host-key, key-reference and tunnel policy. `file`, `git`, `ext`, remote helpers, URL userinfo/query/fragment, control characters, option-like refs and revision expressions are rejected. Git command policy disables hooks, global/system config, credential helpers, redirects, submodule recursion, and LFS smudge. Credential injection is ephemeral and origin-bound inside the executor, never a command argument. No inherited SSH agent is allowed.

The default Git host policy allows public `github.com:443` only. Administrators can explicitly add an exact HTTPS host/port and optional private CIDRs for internal Git. Every resolved address must satisfy the host policy; private ranges require explicit administrator CIDRs, while loopback, link-local, multicast, unspecified, and metadata endpoints stay denied. The executor must pin validated DNS results, enforce policy at connect time and through a proxy, and refuse redirects. An HTTP proxy that performs DNS remotely must enforce the same upstream target policy; merely checking DNS in Core is insufficient.

Proxy tests accept only a server-owned target ID and HEAD method, no arbitrary URL, body, redirect or port. They run in the same safe execution environment as acquisition, with a 5-second deadline, 4 KiB response cap, concurrency/rate bounds and no automatic retry. Profile schemes are HTTP/HTTPS/SOCKS5/SOCKS5H; support is negotiated per phase by the executor. Git's HTTP transport may support these via libcurl; npm/pnpm/Yarn and pip do not share one SOCKS guarantee. Unsupported phase/scheme pairs fail explicitly. There is no silent direct fallback.

Snapshots are capped at 50 MiB compressed, 200 MiB expanded and 3,000 files. Links, traversal, devices, ambiguous names, sensitive credential paths/content, submodules and LFS pointers are rejected. Subdirectory selection is relative and cannot escape or follow links. Resolve/fetch/export deadlines and cancellation are independent. No automatic import/build/deploy/start replay occurs after uncertain completion; existing idempotent-operation reconciliation applies. A worker termination request is not terminal evidence until the executor returns.

## Dependency plan contract

Restart reconciliation persists orphaned `queued`/`running`/`cancel_requested` imports as `interrupted` before the supported single coordinator accepts work. This releases its four-slot queue, not an executor's physical resource reservation. `terminal=true` ends coordinator polling; `execution_state=unknown`, `execution_terminated=false` and `requires_reconciliation=true` explicitly preserve the unknown execution outcome. Cancellation cannot report success for such an operation. The original import and idempotency key remain queryable; no write is resumed or blindly replayed. The Native adapter now reconciles its own durable job/container/cgroup records before dispatch; unknown outcomes block readiness. Isolated build restart outcomes also remain interrupted and cannot be deleted or blindly replayed.

An executor's ordinary `InterruptedError` also records an unknown outcome and retains its profile guard. `SafeExecutionCancelled` is reserved for a trusted executor that has confirmed phase and descendant termination. Coordinator cancellation before execution or after the executor has returned can finish as cancelled; merely requesting cancellation cannot.

Proxy deletion guards follow live resource lifetimes. Reusable unexpired plans, active/unknown imports, retained uploads/builds and current defaults protect their pinned revisions. Expired plan guards are pruned during planning/reference inspection/deletion; known-terminal imports release theirs. Actual upload/build deletion releases its guard in the same database transaction. Historical plans, audit and immutable version snapshots remain, without permanent deletion guards. Unknown/interrupted executions retain protection until their outcome is reconciled.

Supported command families: npm 9–11 with package-lock/shrinkwrap v2/v3 (`npm ci`), pnpm 8–11 with a matching lockfile format (`pnpm install --frozen-lockfile`), Yarn Classic 1.22.x with a v1 lockfile (`yarn install --frozen-lockfile`). Yarn Berry uses different immutable/PnP semantics and is explicitly unsupported in this increment. Required Node installation without a lockfile is blocked; copy-only projects remain supported.

An exact `packageManager` declaration or explicit project override pins the version. A missing tool or different installed version produces a **tool preparation step** in the same confirmed BuildPlan. A safe executor prepares the pinned official npm/pnpm/Yarn distribution using the selected installation proxy/registry, verifies the official registry integrity, records version/source/integrity, and caches by manager/version/integrity outside project artifacts. It extracts reviewed official distributions without running their install lifecycle. Corepack is not a prerequisite: the controlled official-distribution path also covers missing/broken Corepack. No host global installation/configuration, floating latest tag, unconfirmed Corepack download, or silent version substitution is allowed. Node engine incompatibility and download/verification failure stop the build. Project lifecycle scripts and tool preparation are visible in the installation/build confirmation.

Lockfiles are inspected only in the actual selected project root. When the declaration/override selects a unique matching lock, other manager locks are retained with a warning. npm shrinkwrap has its documented native precedence. True ambiguity returns structured choices that can be saved in the actor's revisioned project delivery draft and passed unchanged into plan/create. Unknown manager versions or incompatible lock formats remain explicit errors. Plans accept only generated preparation/install/build commands and matching dependencies. A Node `bin` entrypoint such as `bin/ssh-mcp.mjs` can be selected when it is a safe relative file. This does not provision SSH keys or run remote commands. Python `requirements.txt` retains its existing behavior; uv/Poetry/other Python managers are not implicitly supported.


Without an exact declaration/override, isolated plans visibly pin policy versions npm `11.6.0`, pnpm `9.15.4`, Yarn Classic `1.22.22`; host PATH is not evidence of executor availability. Every isolated Node command plan verifies/prepares its versioned cache explicitly, even if a matching host tool exists. Prepared tools stay in the executor cache: they do not silently become runtime tools. A package-manager `scripts.start` launch requires a reviewed runtime with the same manager/version; direct Node `bin` entrypoints avoid that separate runtime prerequisite.

## Supported dependency matrix

These are bounded source/plan rules, not a claim of tested real installs or full Native cache support. The Native adapter supports npm registry-only cache installs; pnpm/Yarn/Python cache installation is explicitly refused. Every requested version must exist in official metadata and satisfy its exact Node engines. Unknown versions fail; the default policy never replaces an explicit declaration.

| Manager | Lock format | Frozen command | Node requirement / boundary |
|---|---|---|---|
| npm 9–11, exact stable version | package-lock / shrinkwrap 2 or 3 | `npm ci` | Verify exact official distribution engines |
| pnpm 8, exact stable version | 6 / 6.0 | `pnpm install --frozen-lockfile` | Verify exact official distribution engines |
| pnpm 9–10, exact stable version | 9 / 9.0 | `pnpm install --frozen-lockfile` | Verify exact official distribution engines |
| pnpm 11, including 11.5.0 | 9 / 9.0 | `pnpm install --frozen-lockfile` | Actual Node >=22.13 **and** exact official engines; no Node auto-upgrade |
| Yarn Classic 1.22.x | v1 | `yarn install --frozen-lockfile` | Verify exact official distribution engines |
| Yarn Berry / pnpm 12 / other Node managers | — | — | Explicitly unsupported; no Classic/npm/version fallback |
| Python requirements | requirements.txt | Existing `python -m pip install -r requirements.txt` | Existing Python/pip flow; no added Poetry/uv/bootstrap support |

Version-specific pnpm 11.5.0 evidence: [official package engines](https://github.com/pnpm/pnpm/blob/v11.5.0/pnpm/package.json), [installation command semantics](https://github.com/pnpm/pnpm/blob/v11.5.0/installing/commands/src/install.ts), [committed 9.0 lockfile](https://github.com/pnpm/pnpm/blob/v11.5.0/pnpm-lock.yaml). Only official metadata/source was read; no pnpm distribution was installed or run. Runtime/tool auto-download and dependency-origin changes must be disabled by the reviewed executor. This is independent of the tools' default behavior.

Executor output is frozen before Gate exports it. Network artifact export has additional 30-second, 500 MiB and 30,000-entry bounds; external/absolute/cyclic/ignored-target links and known network secrets are rejected, while contained relative package links are preserved. These checks are defense in depth and cannot isolate a live hostile process. Imported Git file digests are rechecked before plans/queueing and worker copy; changed snapshots require a fresh import/confirmation.

## Acceptance evidence

Generated manager-based local start manifests contain validated `launch.toolchain` manager/version pins and a symbolic tool command. Read-only Manifest validation executes no program; it checks only the service administrator's registered tool paths/file metadata and reports exact versions as unverified. Only the existing local stdio/managed HTTP startup clients probe the registered Node and reviewed JS CLI, then execute that same pair after startup authorization. Absolute project commands and project/host PATH cannot select the probe or interpreter. Missing/unsafe registrations, mismatches and unverifiable versions block. See [administrator registry and legacy compatibility](configuration.md#delivery-network-configuration). The version probe remains credential-free in an empty directory, with five-second/128-byte bounds; those bounds do not establish trust. Core never probes or executes pinned tools. No runtime install, build-cache borrowing, delivery-proxy inheritance or remote bridge was added. pnpm 11 checks the actual registered Node >=22.13; reviewed direct Node entrypoints and legacy unpinned manifests retain their existing authorized behavior without this manager pin. Local execution remains unsandboxed; administrator tool integrity is a prerequisite.

The 0.4.0 validation runs Python, Console and browser regressions in isolated synthetic environments. Git/network tests use controlled fake adapters without connecting user repositories, proxies or SSH. Bilingual layout covers 1600×900, 1920×1080, 2560×1080 and 2560×1440; actual counts, skips and CI status are recorded in [release validation](release-validation.md). These historical results do not establish real acquisition/install. The Native adapter is now implemented with additional synthetic regressions; physical host acceptance remains untested.

Successful plan creation audits only actor, plan ID and digest without recording source URLs or proxy values. Each sweep removes at most 100 expired unused plans; unused plans are capped at 32 per actor and 256 globally. Any import reference preserves its plan provenance, including failed or cancelled imports.
