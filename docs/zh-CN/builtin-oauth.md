# 内置 OAuth 授权

[English](../builtin-oauth.md) · [外部身份提供方](external-connections.md)

内置授权服务器**默认关闭**，复用已有 Gate 用户、角色、资源授权、已发布工具分类、调用配额和审计记录。API token 与外部 RS256 身份提供方模式继续可用。客户端密钥只验证登记的应用；每个人仍须使用自己的 Gate 账号登录，并同意明确的工具范围。

## 只配置，暂不启用

在**连接基础设施 → Gate 内置 OAuth**，保存固定 HTTPS issuer 域名，例如 `https://gate.example.com`，不含路径或末尾斜线；资源填写 `https://gate.example.com/mcp`。Issuer 和 resource 是管理员固定的可信配置，不能从请求 Host 或 forwarded Host 推导。本版只支持 `/mcp` 资源路径。Issuer 必须指向此 Gate 实例，授权浏览器页面与相关 API 必须使用该 issuer 的同一来源。

页面从保存的 issuer 自动生成授权、令牌、发现和 JWKS 地址。保存配置不会生成签名密钥、启用 OAuth、启动网络服务或验证连接。初始化只建立数据库结构。准备部署时须明确点击**生成 / 轮换签名密钥**；私钥使用 Fernet 加密后存入 SQLite，加密密钥位于受保护的 `data_dir/oauth-signing.key`。数据库与此文件必须一起备份，并与公开配置分离。加密密钥丢失时关闭式失败；重新生成加密密钥不能恢复已有私钥。POSIX 要求文件模式为 `0600`；Windows 运维须用 ACL 将访问限定为服务账号。

登记静态客户端名称、**精确 HTTPS 回调地址**及允许的 `tools.read` / `tools.invoke` scopes。不能使用通配符、片段、用户名密码或保留的 OAuth 响应查询参数。其他既有查询参数会保留。Gate 生成 Client ID，只在创建或轮换响应中展示一次客户端密钥，请保存到客户端的秘密配置中。客户端列表不返回密钥。轮换后旧密钥、未兑换授权码和已有令牌族立即失效，需要重新连接。停用客户端后下一请求拒绝；重新启用不会恢复已撤销的令牌族。

一次性密钥窗口须明确点击**已保存，关闭**，或在关闭图标、Escape 触发时确认。复制到剪贴板不等于已安全保存。客户端筛选无匹配时提供**清除筛选**；尚未登记客户端有单独提示。

客户端管理和签名密钥操作需要 `external_connections.manage`。查看和缩小本人授权需要 `credentials.manage.self`。管理 API 保持在私有 `/v1/auth/oauth/*`，授权服务器签发的凭据不能访问管理 API。Gate 认证必须开启。外部模式仅在使用同一规范 MCP 资源且 issuer 不同时可并存。

## 启用与连接

先检查 TLS、精确回调、签名密钥备份、用户权限和下方代理放行清单，再启用。修改 issuer/resource 必须先关闭。关闭会撤销所有令牌族和未完成请求/授权码；重新启用后须重新取得用户授权。已有授权记录保留供查看和撤销。

使用支持**预定义 Client ID 与客户端密钥**的配置入口，采用 `client_secret_basic` 或 `client_secret_post`。本版不声明 CIMD、动态注册或 `private_key_jwt` 支持，不能用于强制这些方法的客户端入口。从 ChatGPT 当前连接管理页面复制精确回调，不猜测或沿用旧地址。平台发现与接入要求以当前 ChatGPT 官方认证与连接指南为准。真实 ChatGPT 连接兼容性需要独立验证。

客户端提交 `response_type=code`、精确登记的 `redirect_uri`、与固定 MCP 资源完全相同的 `resource`，以及 PKCE `code_challenge_method=S256`。申请 scopes 必须属于该客户端允许范围。`tools.read` 对应只读工具，`tools.invoke` 对应写工具；需要两类工具时申请两者。Gate 不实现 implicit、密码 grant、client credentials 或匿名授权流程。

专用 `/oauth/consent` 页面显示真实登记客户端、固定资源、申请权限与登录的 Gate 账号。用户可在最多 100 个 MCP、5,000 个符合条件的工具中搜索筛选，跨 50 行页面明确选择工具，设置 1–30 天期限及调用配额，然后允许或取消。工具默认不选。只显示当前获准且已发布的工具。专用 Secure、HttpOnly、SameSite=Lax Cookie 仅作用于 `/oauth`，不会登录 Console。会话最多 30 分钟，复用已有 Gate 密码校验。需要修改初始密码的用户须先在内部 Console 完成改密。

会话用途由 SQLite 强制校验，不只依赖 Cookie 名称或路径。迁移 `0007_auth_session_purpose` 将已发布版本的既有会话标为 `console`；公网登录只创建 `oauth_consent` 会话。双向复制 Cookie 值不能改变用途；退出也按用途删除会话。不存在的用户名使用固定 dummy hash，经过相同的 200,000 轮 PBKDF2 校验；公网登录对未知用户和错误密码返回同一错误并应用同一准入限制。这统一密码计算成本，不保证所有可观测响应时间相同。

该迁移假设来源为已发布、仅 Console 会话的版本。**不支持从早期未发布 OAuth 候选直接原地升级**：使用新版前，须通过独立审查的离线迁移使这些候选的全部旧会话（同意及 Console 会话）失效，或从新数据库/匹配的已发布版本数据库开始。不能把旧候选同意会话重新标为 Console。迁移不会识别其来源或自动使其失效；禁止先启动新二进制再清理。

旧二进制不会校验新增用途列。禁止带着仍保留公网同意会话的数据库回滚旧版；须使用匹配的升级前备份，或先独立审查迁移方案，移除这些会话后才能启动旧版。本开发任务不执行回滚或删除数据。

MCP 名称取自真实服务 manifest，ID 次级显示；名称缺失时明确标示。搜索覆盖工具名称、ID 及 MCP 名称/ID。**全部 / 只读 / 写入**可以直接选择，默认全部。**重置筛选**恢复搜索、MCP、读写和分页默认值，保留勾选工具；**清空选择**是独立操作。

请求 10 分钟后到期。CSRF/浏览器不匹配、登录过期、客户端配置变化、权限变化和重复提交均有明确错误和恢复操作。刷新授权信息会重新计算可选范围。已完成的允许操作不会再次返回授权码：返回客户端检查，或重新发起授权。成功和拒绝的授权响应保留 state，并返回固定、精确的 `iss`。

## 令牌与权限合同

| 项目 | 边界 |
|---|---|
| 授权码 | 随机秘密，只存摘要，60 秒有效，单次原子兑换；绑定用户/授权、客户端、精确回调、资源、scopes 和 S256 challenge。摘要记录保留期间，正确绑定的重复兑换还会撤销该授权的令牌族。 |
| 访问令牌 | RS256，包含不可变 Gate 用户 `sub`、`client_id`、`gid`、`fid`、`aud`、scopes、`jti`、`iat`、`nbf`、`exp`；最长 10 分钟，不超过授权/令牌族期限。本地公钥验证不访问网络。 |
| 刷新令牌 | 随机秘密，只存摘要，每次成功刷新轮换。令牌族绝对期限最长 30 天，并受授权到期约束。已用令牌重放先提交整族撤销，再返回 `invalid_grant`；错误 scope 的重放也不能回滚撤销。 |
| 缩小授权 | 刷新 scopes 只能缩小。**我的连接 → Gate 内置 OAuth** 可移除工具、缩短期限、降低配额或撤销。扩大范围需要重新同意。 |
| 当前策略 | 当前及旧握手协议均逐 MCP HTTP 请求重新读取有效用户、客户端、授权和令牌族。工具调用在请求解析和排队后、派发线程内再次认证。握手和下游会话不缓存入站主体或 bearer。当前角色/资源权限、已发布分类、JWT scopes 与保存的工具快照取交集。重新分类、变更或新发现工具不会自动进入旧授权。纯展示 MCP 更名不改变工具范围。 |
| 签名密钥轮换 | 新加密 RSA 私钥签发新令牌，旧公钥保留 10 分钟；退休密钥拒绝验证。JWKS 和管理响应均不公开私钥。 |
| 配额 | 复用外部 OAuth 的每授权速率/并发边界，仅在单 Core 进程计数，重启后重置。SQLite 部署要求单写入者/Core。 |

`POST /oauth/revoke` 使用客户端认证，接收访问或刷新令牌并撤销对应令牌族。未知令牌和其他客户端的令牌返回相同成功响应，不泄露其状态。用户撤销授权会撤销该授权的所有令牌族。停用/撤权在下一请求生效，不取消已经执行中的下游操作。

已用刷新令牌的摘要保留到令牌族到期。授权码记录到期后再保留 10 分钟，之后可以清理。每族最多轮换 10,000 次，超过后需要重新授权。最多登记 100 个客户端，每客户端最多 10 个回调，每用户最多保留 1,000 个授权。单授权工具范围最多 5,000 个工具、100 个 MCP。在已登录请求准入或完成时清理过期交互、令牌族与授权码，不自动删除授权历史。

匿名 authorize/context 使用绑定浏览器的加密票据，TTL 为 10 分钟、大小上限 16 KiB，不建立待处理数据库行。票据密钥采用标准 HKDF-SHA256，与私钥加密分离用途。票据绑定请求、浏览器、CSRF 和配置/客户端版本；关闭后重新启用会使旧票据失效。迁移 `0008_oauth_interaction_capacity` 要求旧短期交互重新发起。已登录待处理池仍为全局 200、每用户 5、每客户端 50，换 IP/Cookie 不能绕过。完成立即释放槽位，丢弃大工具目录/请求，只保留到票据到期的小型重放记录；上限独立为已登录全局 3,072、每用户 64、匿名 1,024。匿名取消不能消耗已登录完成预算。退出及检测到登录过期会释放待处理容量；到期清理回收遗留槽位。

## 公网代理放行清单

只按下方方法公开这些路径。公网入口阻止其他路径，包括 `/console`、`/v1`、`/docs`、`/openapi.json` 和服务管理接口。内部 Console 使用独立私有监听或来源。不要配置所有路径直通 Gate 的 catch-all 代理。

| 路径 | 公网方法 | 用途 |
|---|---|---|
| `/mcp` | 既有 MCP 方法 | 受保护 MCP 协议，保留令牌/策略检查 |
| `/.well-known/oauth-protected-resource`、`/.well-known/oauth-protected-resource/mcp` | GET | 固定资源和配置的签发方发现 |
| `/.well-known/oauth-authorization-server` | GET | 内置授权服务元数据 |
| `/oauth/jwks` | GET | 公共签名密钥 |
| `/oauth/authorize` | GET | 校验授权请求并打开专用页面 |
| `/oauth/consent`、`/oauth/assets/*` | GET | 专用界面及其独立编译资源 |
| `/oauth/context` | GET | 绑定浏览器的请求、账号、工具信息及 CSRF token |
| `/oauth/login`、`/oauth/logout`、`/oauth/decision` | POST | 同源 JSON，要求浏览器 Cookie 和 CSRF |
| `/oauth/token`、`/oauth/revoke` | POST | 表单编码、静态客户端认证的协议接口 |

此模式必须使用 TLS。浏览器 POST 的 Origin 必须精确等于 issuer，不提供跨来源 API 访问。管理会话写入要求内部 Console Origin。公网只需要独立 OAuth bundle；`npm --prefix web run build` 分别编译 Console 与 OAuth，Python 包资源和 Docker 会复制两棵资源树。公网无需 Console 资源或 `/v1/auth/login`。

请求体读取期限为 5 秒：普通接口最多 32 KiB，同意和缩小授权接口最多 2 MiB；授权查询最多 8 KiB、context 查询最多 32 KiB，最多 20 个字段，拒绝重复字段。每来源每分钟登录最多 10 次；发起授权、同意最多 30 次；context 最多 60 次。已登录浏览器操作以不可变用户 ID 限流，匿名以解析后的客户端 IP 限流，各通道分别限制来源跟踪数量。

浏览器/发现通道的每分钟共享上限相互独立：匿名发起授权 150、登录 120、公开 context/退出 300、匿名取消 60、发现 240、已登录浏览器操作 400。

协议端点先按解析后来源对**每个端点**限制 60 请求/分钟，在读取请求体之前低成本准入，不再共享未认证全局协议预算。畸形请求止于这一层；凭据语法、未知/停用客户端和错误密钥统一返回 `invalid_client`，每来源/端点 10 次失败后返回 `rate_limit_exceeded`。失败跟踪使用来源，不使用未经验证的 Client ID。来源仍有入站容量时，之前的认证失败不会阻止有效凭据通过。为区分凭据失败，仍执行有界、低成本的只读客户端检查，不取得 OAuth 写事务、不签 JWT、不查找或撤销令牌族。

只有客户端凭据通过校验后才消耗下列独立操作预算。全局上限总计仍为原来的 **600/分钟**，通过保留容量解决隔离问题，不扩大阈值。交换/刷新/撤销事务在准入后再次校验当前客户端状态；并发停用或轮换不能使变更获准。

| 协议操作 | 每已认证客户端/分钟 | 已认证操作共享上限/分钟 |
|---|---:|---:|
| 授权码交换（含客户端认证后的不支持 token grant 尝试） | 30 | 180 |
| 刷新 | 60 | 300 |
| 撤销 | 30 | 120 |

协议入站和失败跟踪分别为每端点保留最多 4,096 个来源，期限一分钟，并淘汰最久未使用项；填满表不会拒绝所有新来源。淘汰和换 IP 时，来源限流为尽力而为。同一解析后代理来源的多个客户端仍共享该端点入站限制；分布式洪泛仍共享 CPU、连接、审计/存储和读取资源。被盗用的有效客户端能消耗本客户端限额，多个有效客户端仍可能耗尽某操作共享上限。公网边缘须配置可信代理 IP、TLS、连接/请求体/频率限制和反滥用控制，并限制畸形及认证失败流量。任意 forwarded header 不能改变 Gate 限流身份。这些边界不保证可用性，也不能替代边缘防护。

OAuth 响应使用 `no-store`。页面禁止嵌入 iframe，采用严格 CSP 与 `no-referrer`，不向第三方资源发送请求秘密。Gate 的 Uvicorn 访问过滤器移除查询并遮蔽未知 OAuth 路径。代理、CDN、链路追踪和 WAF 日志必须排除 OAuth 查询/请求体值、密码、授权码、令牌、PKCE verifier 和客户端密钥；Gate 无法控制这些外部日志。禁止在这些路径采集请求体。

## 审查与验证状态

本实现只进行了静态检查，没有启动 Gate，也没有运行 OAuth、网络或浏览器验收。自动化测试代码覆盖精确回调、PKCE 错误、码到期/重放、码和刷新并发、重放整族撤销、scope 上限、所有权、实时停用/撤权、签名轮换、CSRF、双向 Cookie 值用途复制、旧会话迁移、dummy 密码计算、匿名洪泛、分层容量及准入隔离、秘密存储、Host 独立性、API token 回归和外部 JWT 回归。完整 MCP 路由测试覆盖当前/旧协议发现后的连续调用与撤权，以及请求解析后、派发前撤权。浏览器测试使用合成模拟 API，覆盖中英文、1600×900、1920×1080、2560×1080、2560×1440，以及 100 MCP / 5,000 工具、筛选重置保留选择、客户端空态和一次性密钥关闭保护。测试存在和编译成功均不代表测试已经执行。

验收前运行 `uv run pytest -q tests/test_builtin_oauth.py`、既有外部/API token 测试、`npm --prefix web test`，构建资源后运行新增浏览器测试。随后使用非生产客户端验证真实 TLS/代理 Cookie、元数据、回调登记、发现、已授权读写调用、拒绝范围、并发刷新、停用/撤权和签名轮换。本开发任务没有配置真实凭据、账号、隧道或连接。CIMD、DCR、多租户和隧道生命周期管理不在本版范围。
