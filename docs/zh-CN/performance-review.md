# 性能检查与可复现验证

[English](../performance-review.md)

## 范围与证据

2026-10-01 检查覆盖控制台加载与渲染、SQLite 审计查询、构建日志流、工具发现与授权、缓存统计、保留清理以及传输资源限制。下列数据来自同一云端开发环境中的一次性合成数据，是热缓存下的函数耗时；不代表端到端延迟、吞吐、生产容量或长期内存泄漏验收。

| --- | ---: | ---: | --- |

## 修复与回归覆盖

- 审计查询新增事务性增量迁移 0003_audit_user_latest_lookup。保留已删除用户的历史名称快照与时间戳/ID 相同情况下的确定性选择；已有数据库迁移与执行计划有测试。真实大数据库建立索引会占用写锁，应保留备份并安排升级窗口。
- 构建 SSE 的数据库读取移入线程池，并使用序号游标增量读取。原实现每次重新加载最早的 1,000 行，不仅重复工作，还会漏掉后续行。2,501 行回归测试验证末尾状态之前完整发送全部批次，数据库读取不占用事件循环线程。
- 缓存大小、文件数和更新时间改为一次遍历。缺失、空目录和非目录路径保留原语义。
- 控制台首次加载、配置修改后刷新不再自动启动运行环境诊断；进入诊断页面或显式操作时才执行。工具/配置的其他初始读取仍保留，本次并非重写所有启动请求。
- 新趋势图采用原生 SVG、缓存几何计算、7/12 个有限时间点、零基线，不引入图表库。切换指标只更新本地显示；组件测试覆盖键盘查看及切换指标不请求统计接口。

三处后端修复之后，全套后端 767 项测试通过，Ruff 与 mypy 通过。前端检查、构建及 306 项测试通过，发生在最后一处空状态布局调整之前。这是对应检查点的证据，不保证后续任何修改自动通过。浏览器布局/交互和 E2E 结果必须单独说明。

## 仍需检查的风险

- 生产主 JavaScript 块约 1,184.75 kB，gzip 约 312.23 kB。页面已有懒加载，需要分析共享依赖与真实冷启动后，才能声称进一步分包改善了加载；单纯切小文件不等于减少下载量。
- 日志/事件历史服务筛选与子串搜索仍可能随历史规模增长扫描大量记录。先按真实保留量和权限组合测量，再考虑索引或物化目录，不得通过减少权限检查提速。
- 构建实时日志的记录数与渲染行数现已限制，见下方补充；单条 stdout/stderr 较大时仍需按字节测量内存。
- SQLite 仍是单写入者、单 Core。真实并发写入、下游 MCP 延迟、锁等待和长期 RSS 尚未做负载验证。传输边界限制和短时函数基准不能证明生产容量。
- 当前环境的完整 Playwright 执行在断言前因 Chromium socket() failed: Operation not permitted 受阻。收集到测试或单元测试通过不能称为 E2E 验收；不绕过浏览器安全限制。

## 安全复现

在仓库根目录执行：

```sh
uv run python scripts/benchmark_performance.py --rows 30000 --cache-files 10000
uv run pytest -q tests/test_audit_lookup_performance.py tests/test_build_log_stream.py tests/test_runtime_cache_summary.py
```

脚本始终创建临时 SQLite 数据库和缓存目录，不读取或清理部署数据库，不启动 MCP，不访问凭据或外部服务。比较时一并记录操作系统、CPU、文件系统与重复次数。CI 应验证语义和执行计划，不把易受环境噪声影响的绝对耗时作为发布门槛。

## 构建日志窗口后续优化

控制台实时日志最多保留 200 条，每页渲染 50 行。SSE 输入按动画帧分批去重与排序；后台标签页暂停动画帧时，缓冲队列达到 200 条也会刷新。历史日志不删除：“更早记录 / 较新记录 / 回到最新”通过服务端序号索引读取窗口。翻页或筛选暂停实时跟随，读取失败保留当前窗口。检索仅覆盖当前已加载窗口，不代表搜索全部服务端历史。

已有鉴权日志接口新增互斥的 before_sequence、after_sequence、tail 参数及 has_earlier/has_later 返回值，默认行为兼容。SSE tail=true 从最新 200 条开始，默认流仍完整读取历史。测试覆盖 2,501 条服务端记录、授权、翻页边界、5 万条合成输入、重复/乱序输入及中英文每页 50 行渲染。本检查点完整后端 769 项测试通过。这是记录数量上限，不是字节级内存保证；大型 stdout/stderr 仍需另行分析。

## 补充运行时与首屏检查

- 单次用户调用原来会深拷贝整个服务工具目录，即使共享凭据路径根本不用这个副本。现在跳过无用拷贝，重连恢复仅快照当前工具，保留元数据变化检查和禁止重放的边界。合成 5,000 工具、每工具 20 个入参字段，20 次进程内回声桩调用的中位数从 219.133ms 降至 0.001ms。这只度量被消除的拷贝开销，不代表真实 MCP 调用只需微秒。
- 明确具备全局读取权限的用户查询全部运维日志/事件时，不再先生成历史服务目录。共享权限策略、令牌权限上限、指定资源校验、限定服务授权和撤权仍有效；API 回归同时覆盖全局优化路径和原有限定路径。
- 全局搜索的专用依赖改为首次使用搜索时加载。加载中与失败时都有可关闭的界面；懒加载失败不能替换整个控制台或自动刷新而丢失编辑内容。诊断命令跳转页面时，也不再和该页面的自动读取重复启动诊断。
- 100 服务、5,000 工具的隔离发现测试连续执行 1,500 次，耗时 241.19 秒，中位数 149.84ms、p95 208.442ms。从第 750 次至第 1,500 次，RSS 采样大多为 93,648KiB，另有一次 92,640KiB。在此观察窗口未出现持续增长，但不能证明长期没有泄漏。
- 本地合成 stdio 回声子进程，8 个调用线程发起 500 次请求，经过 Gate 授权与 SQLite 审计，500 条审计均成功。耗时 1.337 秒，中位数 22.141ms、p95 28.847ms。本次由注册表处理函数直接连接受控客户端，不据此宣称完整运行管理器、真实外部业务、HTTP/OAuth 或生产容量已经验证。

可在没有生产实例的情况下复现隔离场景：

```sh
uv run python scripts/benchmark_discovery.py --iterations 1500
uv run python scripts/benchmark_stdio.py
```

两者均使用一次性临时目录与合成身份。仅在存在 `/proc/self/status` 时报告发现测试 RSS。stdio 场景只执行自身生成的本地回声子进程，不联网，也不使用外部凭据。不要加入默认快速 CI 流程。
