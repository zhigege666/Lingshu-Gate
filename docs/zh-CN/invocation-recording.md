# 调用内容记录

[English](../invocation-recording.md)

Gate 默认只记录调用元数据。持久化保留策略的 `payload_mode` 默认为 `metadata_only`；只有具备 `retention.manage` 的管理员明确改为 `redacted` 才记录脱敏内容。这不能重建以往的输入输出。记录的 `recording_mode` 表示调用发生时的模式，而不是当前策略。

## 访问和结构

`GET /v1/me/invocations/{audit_id}` 要求当前认证、有效用户与 `console.view`，并同时按记录 ID 和当前用户 ID 查询。猜测他人的 ID 返回 404，管理员访问个人接口也不例外。`GET /v1/access/invocation-audits/{audit_id}` 单独要求 `audit.payload.read`；`audit.read` 不包含内容读取权。新能力默认只授予管理员角色，Bearer Token 的 scope 上限仍然有效。每次读取都会重新判权，停用用户或撤销内容能力后旧会话的后续请求也被拒绝。

响应包含安全的 `audit` 元数据、`recording_mode` 以及 `input`/`output` 信封。`status` 为 `recorded`、`not_recorded`、`not_invoked`、`truncated` 或 `serialization_error`。存在的 `value` 保留 JSON 的 `null`、`false`、`0`。输出结构为 `{ok, output, error}`；错误同样脱敏。控制台复制前再次请求详情并重新判权；刷新失败会清除已展示内容。已交付的数据无法追溯收回。

## 记录边界

输入在下游凭据注入之前、下游可能原地修改参数之前完成快照。权限拒绝及缺少凭据的调用只记录元数据，内容状态为 `not_invoked`。输入和输出各最多 32 KiB JSON，合计最多 64 KiB；深度最多 12 层、值节点最多 1,000 个。截断和序列化限制明确标识，不对不支持的对象调用 `repr` 或任意序列化钩子。

敏感字段名、Bearer 字符串、Authorization 头和 Cookie 行会脱敏。运行时复用客户端已解析的共享凭据及同次解析的个人凭据，对持久化的输出及错误再次脱敏，包括无标签回显；不会重复解密查询或枚举整个凭据库。审计处理不改变实际工具响应。秘密仅在单次调用局部保留，审计回调只接收限长脱敏后的快照。元数据模式不捕获内容。

无法保证识别普通字段名中的任意业务秘密。只有在工具及其数据适合记录内容、并经过组织数据处理评估后才启用；否则保留默认元数据模式。调用内容存储不是凭据存储的替代品。

## 保留与部署

内容与调用元数据在同一事务写入。内容随对应调用记录按调用记录保留天数一起删除；运行日志、事件各有独立保留天数。启用记录无法恢复以前未记录的内容。立即清理须先预览并独立确认不可逆操作。测试只使用独立合成数据库，安装改动不代表已授权清理真实用户数据。

SQLite 仍只支持单写入方、单 Core 部署。内存调用配额在 Core 重启后重置，不能为多个 Core 提供共享限额；不要假定多实例具有全局配额或清理协作保证。

## 验证

`tests/test_invocation_payloads.py` 覆盖标量保真、字节/深度/节点限制、循环引用、真实 HTTP 本人及能力隔离、旧会话停用/撤权、拒绝时下游零调用、调用前快照、错误脱敏及个人凭据回显。下游回显传输使用合成替身，不代表真实外部 OAuth 提供方或隧道连通验收。
