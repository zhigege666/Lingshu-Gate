## 目标与现状依据

用户希望授权一个 MCP 的所有工具后，该 MCP 更新、发现并发布的新工具自动获得授权，不再逐项选择。

设计前核实的能力：

- `web/src/pages/access-grants-page.tsx` 已提供“整个 MCP 服务”，保存服务级资源授权；`src/lingshu_gate/access_control.py::_effective_access_map` 按调用时的服务/工具计算权限，用户工具授权优先于用户服务授权，角色范围在各角色内覆盖后取最高权限。
- `src/lingshu_gate/oauth_server.py::_grant_tools` 只解析 grant 中已保存的工具，并核对当前工具快照。新发现或重新分类的工具不会自动进入旧 OAuth 授权。
- `web/src/features/external-connections/oauth-api.ts` 中业务授权的范围契约是具体工具；现有“MCP 整组”仅批选当前工具。`docs/zh-CN/builtin-oauth.md` 已明确其快照语义。
- `src/lingshu_gate/external_connection.py::UserExternalGrant.allows` 对外部签发方同时检查服务与工具 allowlist；它与内置 OAuth 是独立授权契约。
- 分类发现、审核、发布相互独立；工具发生契约变化会使分类失效。实施阶段已运行相关权限回归。

设计结论：主要缺口是连接授权缺少持久的服务范围策略。后续实现已增加服务策略持久化与运行时校验。以下保留目标行为与验收要求；实际已验证范围以文末记录为准。

## 统一入口与管理对象

用户已选择第一张，并要求合并“Gate API 令牌”和“我的连接”，最终命名为“我的授权”。统一产品对象为“访问授权”：谁通过哪种认证方式、在什么资源范围及期限内访问 Gate。统一入口命名“我的授权”，不保留独立的“Gate API 令牌”侧栏项；授权方式作为列表字段和筛选条件，不再分散成互不相通的顶层页面。

当前源码依据：`web/src/routing/console-routes.ts` 中 `myConnections`、`personalTokens` 均要求本人认证与 `credentials.manage.self`；`web/src/pages/personal-workspace-page.tsx` 将前者交给 `ExternalGrantsPage`，后者由 `App.tsx` 单独渲染 `PersonalTokensPage`。`web/src/api/identity-access.ts::PersonalToken` 提供名称、前缀、scopes、期限、撤销时间、最近使用和创建时间；其创建接口不接受 MCP 策略。`src/lingshu_gate/auth.py::_principal_from_api_token` 只加载本人及令牌 scopes，不能描述为已经存在逐 Token MCP allowlist。

统一交互和范围策略，不强制合并底层凭据表、OAuth grant/family 或协议。使用按类型适配的只读列表模型与操作入口，复用现有后端职责，不为此次设计重写认证协议。

| 授权方式 | 如何产生 | 特有操作与限制 |
| --- | --- | --- |
| Gate API 令牌 | 本人在 Gate 创建 | 明文只显示一次；配置客户端时仅本次创建态可填真实值；之后使用前缀识别，不重新读取明文 |
| Gate OAuth | 客户端发起并完成本人同意 | 展示真实客户端及精确资源；有效授权可按现有 scope 调整范围；缺失 scope 需要重新 OAuth |
| 外部 OAuth | 外部提供方认证，Gate 绑定身份并保存个人范围 | 继续执行原身份映射和提供方约束；Gate 撤销个人范围不等于撤销外部提供方令牌 |

业务与独立管理资源作为另一维展示；即使同一客户端，两者仍是独立行。管理连接显示“管理”用途，并进入现有精确目标编辑器，不提供业务 MCP 持续授权。下游凭据用于 Gate 访问 MCP，方向与本页相反，仍保留现有入口。

### 统一列表

页面身份为“我的授权”，沿用全局导航与紧凑 `PageHeader`，不再叠加独立大标题、副标题或介绍段落。提供一个主按钮“新增授权”，菜单按真实能力显示“创建 API 令牌”“查看 OAuth 接入说明”“配置外部身份授权”。OAuth 接入说明引导从客户端完成授权；不能点击按钮就在 Gate 伪造一个已经连接的 OAuth 客户端。

表格列固定为：授权名称、授权方式、访问范围、调用配额、状态、有效期、操作。名称下显示可识别的令牌前缀或客户端名称及短 grant ID；完整 ID 放详情。“访问范围”用“3 个 MCP · 持续授权 2 个”或“跟随账号资源权限”表述，不将 scope 数当工具数量。“调用配额”紧凑显示 `6000 / min`、`并发 100`，实际值按记录回填。搜索支持名称/客户端/精确 ID；筛选包含授权方式、业务/管理用途及状态。默认有效记录；历史可查。

API 令牌的名称是用户自定义用途标签，不足以证明客户端已连接；详情可展示真实 `last_used_at`。OAuth 当前接口未提供最近使用时显示“未提供”，不补造时间、不由创建时间推算。主表不强行增加所有类型都缺失的列。

共有操作为查看详情、调整授权、撤销；具体操作按服务端能力与状态显示。API 令牌详情提供接入配置，但不再显示已有秘密；OAuth 详情提供客户端和资源。没有后端支持的通用“暂停”“续期”“旋转”“重命名”不出现在首版。已撤销/到期保持只读历史。

聚合读取保留 `kind + source_id`，不按名称/客户端 ID 去重，不把同一客户端的多个 OAuth grants 合并成一条。不同来源的撤销按原 ID 派发，不因合并页面撤销其他授权。各来源失败独立提示“API 令牌读取失败”等，保留其他已读数据，不将失败来源显示为零条或声称目录完整；未读来源时总体数量显示“已加载 N 条”。统一排序/分页只描述完整已加载的本人集合，未来改服务端聚合分页时另行明确总数合同。

### 统一授权编辑器

沿用第一张的 MCP 行列表：每行选择“不授权 / 持续授权 / 指定工具”，使用全局规范要求的三个可访问单选选项，持续模式再选只读/读写。顶部显示授权名称与授权方式，底部先核对完整差异再保存；不附加段落说明或常驻提示条。不能同时用“未选中行”和“已授权模式”表达相反状态；不授权是明确的行状态，复选框如用于批量操作必须与授权状态区分。

将“功能权限”和“MCP 资源范围”分开说明：功能权限是 tools.read、tools.invoke 及 API 令牌可能具有的运维控制权限；MCP 范围决定允许使用哪些业务服务与工具。API 令牌保留现有分组 scope 选择器，在“功能权限”折叠区编辑，当前管理员/普通账号默认值不变。MCP 授权不会自动勾选 operations.manage、classifications.manage 或其他控制权限；控制权限变化也不能绕过所选业务 MCP 范围。OAuth 不展示 API 令牌的全部控制权限选项。

新建 API 令牌：填写名称、期限与配额 → 明确选择功能权限及 MCP 范围 → 服务端核对 → 原子创建凭据与策略 → 一次性展示明文和接入配置。业务 MCP 范围默认不选；现有功能 scope 默认不改变。只需运维控制的凭据可以明确选择“仅控制功能，不开放业务 MCP”，否则空范围必须解释为没有业务访问，不能被解释为全部服务。明文显示态退出需保留现有保护；只在创建成功响应中存在，不进入列表状态、持久化浏览器缓存或日志。创建响应丢失时不能自动重复创建以获得另一枚 Token，须先读回实际记录并明确处理无法恢复的明文。

现有 API 令牌迁移显示“跟随账号资源权限（现有模式）”，继续按原账号资源权限和 scope 生效，包括原先对新增服务的继承行为。不将其转换成当前工具快照或声明等同于显式订阅几个 MCP。本人点击“改为独立 MCP 范围”后，在同一编辑器选择持续/指定策略并预览权限收紧或扩大。未来返回跟随账号模式属于明确的范围变更，须单独预览确认；首版不提供此返回按钮。

逐 API 令牌 MCP 策略属于新增后端能力，须扩展创建/读取/预览/更新合同及每请求的授权链。新策略只约束业务 MCP 工具，不能误伤或隐式放开内置控制工具；控制接口继续校验各自权限和目标。现有管理员 API 令牌可能存在分类旁路；采用新的独立业务 MCP 策略后，拟按显式策略强制检查已发布分类，并在转换预览中显示因此失去的访问；旧令牌不因列表合并改变行为。此差异是明确的设计决策，不能仅复用旧管理员旁路而宣称完成新策略。

### 导航与状态兼容

移除侧栏重复入口；旧 `#/personalTokens` 明确跳转到“我的授权”并设为 API 令牌筛选，旧 `#/myConnections` 进入统一列表，保持既有路由 ID 可达，统一用户可见名称。仅是有说明的界面导航迁移，不重命名 API、cookie、工具或数据库身份。权限仍是本人认证及 `credentials.manage.self`；不能因聚合展示提升可见性。

切换授权方式筛选不丢草稿；打开另一连接或离开页面时沿用未保存保护。编辑器以 `kind + source_id` 绑定读写与异步响应，禁止前一行响应覆盖后一行。保存使用来源各自版本，不伪造一个无真实数据版本支撑的通用 CAS。API 策略新增版本与确认合同，OAuth 复用现有合同，外部授权适配其既有版本。

## 调用配额：默认值与可编辑范围

用户已明确要求新建默认每分钟 6000 次、并发 100，并可编辑两项数值。此处覆盖早期设计中配额只能维持或收紧的限制；授权到期时间的既有收紧规则不随之改变。

源码可证实：`web/src/pages/oauth-consent-page.tsx` 当前默认 `30 / 1`；外部授权 `newGrant` 也为 `30 / 1`，不能把用户提及的 300 描述成当前源码默认。`web/src/pages/oauth-grants.tsx` 从实际 grant 回填，但输入 `max` 被设置为原值；`oauth_server.py::_scope_target` 和 `narrow_grant` 也限制不能提高。现有 OAuth 同意及请求模型允许每分钟 `1–10000`、并发 `1–100`，新默认 6000/100 在该边界内。源码事实不代表现场配额已经变化。

| 场景 | 数值来源 | 编辑与保存规则 |
| --- | --- | --- |
| 新建业务 API 令牌、新建业务 OAuth/外部个人授权 | 新默认 6000/100 | 用户可改成边界内正整数；前端初值与后端省略字段默认必须一致 |
| 编辑已有 OAuth，例如每分钟 300、并发 1 | 后端当前实际值 | 可提高到 6000/100，也可调低；不在打开编辑器时自动改值 |
| 老 API 令牌没有独立配额字段 | 当前未设置 | 列表/详情显示“未设置”；开始配置时提供 6000/100 草稿，明确保存后才生效，不声称原本有限流 |
| 仅编辑配额，不改 MCP 或 scope | 原工具和策略保留 | 必须可保存；不能要求顺便重选工具或扩大 scope |
| 当前 scopes 较小 | scope 保持原上限 | 提高配额只改变频次/并发，不增加工具、控制功能、期限或 OAuth 能力 |
| 已撤销、过期或不属于本人 | 当前记录 | 只读；拒绝更新，不能借调整配额复活授权 |
| 空白、非整数、0、负数或超过边界 | 非法草稿 | 保留输入并在字段旁校验；不静默回填 1、旧值或默认值 |
| 页面刷新或来源读取失败 | 未取得可信值 | 不以 6000/100 覆盖现有记录；保留草稿并提供重读 |

“调整授权”弹窗工具表上方提供两个 `InputNumber`：标签“每分钟调用上限”“并发上限”，固定宽度左标签、右控件；宽屏可同行，窄屏分成两行仍保持左右结构。字段显示实际数值，精度 0；配额不是折叠的只读信息。新建的初始显示为 6000、100。已有记录必须先读值，单独修改任何一项均触发 dirty、预览和保存。

服务端预览返回前后配额，确认区精确展示“每分钟 300 → 6000”“并发 1 → 100”。本人确认后以 CAS、单次确认和原子审计提交；允许在已有数值边界内调高调低，不再将原保存值作为新上限。复用既有更新链并扩展其明确目的，旧的只缩小 PATCH 保留原合同；不能为图方便直接放宽所有 `narrow_grant` 调用。新 API 令牌须增加按凭据身份限流的真实后端存储与执行能力，不能只在页面保存数字。独立管理资源保留单独合同，其既有配额展示不因此被隐式扩大；本次新默认与可调高规则应用于统一业务授权。

拟定计数口径为一次授权的业务工具调用总量，跨 MCP 共用；API Token 按 Token ID、内置/外部 OAuth 按其 grant ID 计数，同一 grant 的不同 family 不获得各自完整新预算。目录读取不描述为工具执行。调整配额不清零已经消耗的频次计数；降低并发不取消已执行的调用，后续准入按新上限判断。配额变更在提交后的下一次准入及实际派发边界使用新值；需核实现有排队与限流实现的同步方式，不能声称已在运行中验证。继续保留现有单 Core 进程配额边界；6000/100 是配置默认，不是吞吐能力或并发压测承诺。

## 授权模型

每个业务连接按 MCP 精确身份保存一种模式；同一个连接可对不同 MCP 采用不同模式。

| 模式 | 用户含义 | 后续新工具 |
| --- | --- | --- |
| 持续授权此 MCP | 授权当前及后续发布的工具 | 符合条件后自动纳入 |
| 仅授权指定工具 | 保持当前精确工具与快照策略 | 需要本人选择并确认 |
| 不授权 | 此连接不使用该 MCP | 不纳入 |

持续授权另选“只读”或“读写”。只读自动纳入发布为只读的工具；读写自动纳入已发布的读、写工具。读写选择须明确说明包含未来写工具。模式和权限等级必须由用户明确选择；不把旧全选状态推断成持续授权，也不默认订阅未来 MCP。

拟新增策略概念：`server_policies[{server_id, server_binding, mode, access}]`。`mode=continuous` 保存服务意图；`mode=selected` 继续使用现有具体工具快照。`server_binding` 表示需要新增或核实复用的不可复用服务生命周期身份，不宣称现有表已经提供此字段。同一 MCP 两种模式互斥，不保存重复的独立全选列表。第一版不增加“持续授权但排除若干工具”，需要例外时转换为指定工具模式。

实际可用范围取以下交集：本人当前资源权限、精确 MCP 持续策略或工具快照、当前有效已发布分类、业务资源、客户端允许 scopes、grant scopes、该令牌自身 JWT/family scopes、授权期限及配额。显式工具级无权限继续覆盖账号服务授权。管理员身份不使 OAuth 绕过分类发布。

“自动获得”指后续 Gate 请求按策略重新解析；不自动修改客户端 scopes、不重新签发更宽令牌、不替用户执行工具、不替管理员发布工具分类。只读连接不能因勾选读写而得到缺失的 `tools.invoke`；界面禁用该选项并说明需要重新发起包含相应 scope 的 OAuth 授权。

## 主流程与页面

主入口改为“我的授权 → 对应记录 → 调整授权”，授权方式以字段展示；初次业务 OAuth 同意页复用相同 MCP 范围语义。“MCP 资源授权”继续负责账号上限，独立范围规则通过帮助入口按需查看。外部签发方和独立管理连接边界见后文。

1. 打开编辑器，先展示连接名称、有效期和当前范围。既有授权回填为“仅授权指定工具”，不静默迁移。
2. 以 MCP 为主列表，显示名称、精确 ID、授权方式、只读/读写，以及“当前可用工具”数量。搜索和分页仅改变视图；不修改已保存范围。
3. 选择“持续授权此 MCP”，通过状态与单选直接表达当前模式；“包括当前及后续发布的工具”等解释按需从帮助入口查看，选择读写后的未来写工具后果在保存确认中明确列出。数量显示为当前值，不能将它描述成永久范围。
4. 指定工具模式才展开现有分页工具选择器。持续模式的“查看当前工具”是只读详情，不显示暗示可逐项取消的复选框。
5. “保存授权”先调用服务端预览。确认区同时显示策略变化、当前新增/移除工具、未来工具是否自动纳入、未来写权限和受限原因；即使当前工具差异为零，模式变化仍是可保存的实质变更。
6. 本人确认后原子保存。短成功反馈“授权已更新”；客户端刷新说明放按需帮助或实际缓存问题的上下文，不常驻页面。不要求重新 OAuth，前提是所需 scope 已存在。

保存确认必须明确显示“指定工具 → 持续授权”“只读 → 读写”等策略差异；取消不改变授权。移除 MCP 持续策略会停止纳入其工具，不自动保留原工具；若需保留则明确选择“改为指定工具”，服务端预览固定当时可授权的完整快照，不能只取当前页。

“清空选择”必须明确是否清除所有 MCP 策略；沿用现有行为时改名为“清空授权范围”，在草稿中清除所有模式，保存时确认。刷新只重算当前结果，保留未保存策略。列表用“持续授权 · 读写 / 当前可用 24 项”区分“指定工具 · 24 项”。

## 更新与异常状态矩阵

| 场景 | 持续模式预期 | 指定工具模式预期 |
| --- | --- | --- |
| 相同服务升级，工具未变 | 继续可用 | 快照匹配时继续可用 |
| 新增工具完成发现，尚未发布分类 | 不可用，显示待发布原因 | 不可选或不可用 |
| 新只读工具完成分类发布 | 只读与读写模式均自动纳入 | 需本人选择确认 |
| 新写工具完成分类发布 | 仅读写策略且令牌 scope 足够时自动纳入 | 需本人选择确认且 scope 足够 |
| 工具 schema/读写分类变化 | 分类失效期间拒绝；重新审核发布后按当前读写等级自动恢复 | 保留现有快照重新确认要求 |
| 工具从读改为写 | 只读策略不再纳入；读写策略在重新发布且 scope 足够后纳入 | 旧快照失效，重新确认 |
| 撤销资源权限、停用账号/客户端、grant/family 撤销或到期 | 下次请求拒绝；不新增授权 | 保留既有拒绝行为 |
| 单个工具明确无权限 | 账号权限检查继续拒绝 | 同左 |
| 同一 MCP 显示名称变更 | 身份未变则保留策略 | 保留既有行为 |
| MCP 删除后用同名/同 ID 新建，或信任目标替换 | 生命周期绑定失效，必须重新确认，不自动继承 | 不通过旧快照复活权限 |
| 只读令牌族，grant 允许读写 | 该族仍只能用只读工具 | 同左 |
| 暂时离线或当前没有可用工具 | 保留持续策略，显示“当前 0 项/服务离线”，不删除授权 | 保留历史详情 |
| 客户端缓存旧目录 | Gate 下次请求已按新策略解析；提示刷新客户端工具列表 | 不承诺客户端自动刷新 |
| 目录或分类读取失败 | 失败关闭，返回结构化原因，不能沿用过期的放宽结果 | 同左 |
| 保存后响应丢失 | 显示结果未知，保留草稿，先读回版本与策略，禁止盲目重放 | 复用现有恢复规则 |
| 编辑期间工具发布或策略变化 | 预览/确认版本失效，保留草稿并重新核对 | 同左 |

同一 MCP 身份必须覆盖真实服务绑定。普通升级与显示更名不解除持续授权；不同信任目标替换不应借“更新”继承授权。实现前必须核实 manifest 更新、项目覆盖部署和删除重建的身份生命周期；这是明确的实现前置检查，不能只凭字符串 ID 推断安全性。

## 实现边界与复用路径

扩展现有范围目录、预览、保存与 grant 解析链，不新增另一套连接管理。复用当前 Console 本人会话、Origin/CSRF、短期单次确认、CAS、事务内权限重检、审计失败回滚和未知结果读回。

- 目录响应增加每个 MCP 的已保存模式、权限等级、当前有效计数和排除原因。模式统计与筛选分离，允许当前零个可用工具的已订阅 MCP 被读取和取消。
- 预览/保存增加版本化策略字段，确认摘要绑定服务身份、模式、读写等级、当前目录版本及策略差异。旧请求只维持原快照语义；未知字段/版本拒绝，不能忽略新模式后声称成功。
- `_grant_tools` 在业务授权中按当前策略解析服务候选，再与当前权限、分类和每个令牌的上限相交。`tools/list`、直接 `tools/call`、搜索/调用转发、排队后派发重检必须使用同一解析依据，不能只放开列表。
- 持续策略是唯一授权依据；当前工具列表只是派生结果，不在发布时给每个用户批量复制 grant，也不以一次展开的 IDs 替代持续策略。
- 初版沿用每 grant 最多 100 MCP、5,000 工具的现有预算，不借此设计宣称无限支持。自动解析超过预算时明确失败关闭并显示范围超限，不能随机截取前 5,000 项、不能静默降级成快照；实现需有界分页/查询，不能每请求全仓扫描。超限后的连接可用性取舍需在实现评审中特别确认。
- 策略保存原子记录操作者、连接、前后模式、服务身份和权限等级。后续发布不产生伪造的“用户重新同意”事件；运行审计记录使用的策略版本和实际工具分类版本，不保存凭据。
- 停用/撤销于下次请求及排队后边界生效；已经发生的下游副作用不声明可以撤回。

既有“仅授权指定工具”授权全部保持原义，迁移不扩大范围。修订后的设计范围包含统一连接列表、新 API 令牌独立 MCP 范围、既有 API 令牌主动转换、内置业务 OAuth 的初次同意与连接编辑。账号资源授权复用既有能力；API Token 的控制权限与账号资源范围保持独立，不把它误作 OAuth 工具快照。外部签发方个人授权可进入统一列表和其现有编辑器；持续模式须单独扩展其策略存储、`allows` 和确认合同后才显示为可选，不能仅清空 tool_allowlist 或展示不可用的假开关。独立 `/mcp/manage` 仍保持四个固定管理工具与精确目标合同，不进入业务 MCP 持续订阅。

## 验收清单与交付边界

实现验收应使用真实生产类型及合成 HTTP 下游，至少验证：同一 bearer 在首次明确持续授权后能列出并调用新发布工具；未发布工具拒绝；只读/读写及 JWT/family scope 矩阵；重新分类恢复；撤权与排队重检；服务删除重建不继承；旧快照不变；混合模式与跨页选择；策略零工具差异仍确认；CSRF/CAS/确认重放/审计回滚；保存结果未知恢复；超限不截断；业务/管理资源隔离。

统一管理补充验收：旧两个入口都可到达正确列表状态；相同名称但不同类型/不同 grant 不串操作；来源读取部分失败不能显示完整总数；缺失最近使用时间不伪造；只撤销目标来源记录；新 API 令牌创建与范围原子提交；明文仅一次且不被列表请求重新获取；空业务范围不等于全部；旧 API 令牌行为不变；主动转换后列举及直接调用均受 MCP 策略约束；API 管理控制 scopes 与业务范围独立；OAuth 缺失 scope 时不能在统一编辑器越权补授。

本次修订补充验收：所有可见入口/标题统一“我的授权”；页面及弹窗无重复介绍与常驻长说明；标签左控件右、单选可键盘操作；新建前后端默认一致为 6000/100；已有 300/1 正确回填并可确认提高至 6000/100；只改配额也能保存；非法输入保留且可定位；配额预览/CAS/审计/未知结果恢复；老 API 令牌未设置配额不伪装成 6000/100；提高配额不扩大 scopes/工具或续期，管理资源规则不被隐式放宽。

界面检查覆盖中英、明暗、键盘操作和现有 1600×900、1920×1080、2560×1080、2560×1440 视口。新增数量必须来自同一后端快照；未提供时显示未知，不推算数字。生成图只用演示数据。

首轮交付概念图，随后按用户确认实现生产代码。概念图不是运行证据；业务 OAuth scopes 使用 tools.read、tools.invoke。API 令牌和内置业务 OAuth 实现持续策略；外部签发方保留原范围编辑，管理资源保留原固定工具合同。
